# 表情生成耗时排查

2.0.0 本次同版本更新在 Blender 4.5.14 LTS 实测睫毛覆盖路径。主瓶颈是覆盖约束的顺序投影，困难输入可执行满 16,384 轮；之前缺少进度更新，耗时会被记到上一条覆盖核对。现在显示「拟合睫毛覆盖约束」，保留约束次序、采样、迭代上限与容差，使用批量截面检查及可回退的 Windows 64 位原生投影循环。

锁暝部件整体分支五个固定输入表情的历史测试中，不启用性能分析器时，求解合计约 124 秒与 28 秒，前后坐标及约束报告完全一致；含性能分析器时约 163 秒与 36 秒。历史诊断输出已在 2026-10-22 清理，模型保留为 `models/suoming.blend`。这不包含输入导出、结果导入或全部表情，不能推广成所有模型的提速保证。原生库加载失败及其他平台继续使用原 NumPy 循环；当时未测其他平台速度。

1.9.26 增加了耗时记录，用于判断时间花在约束、曲线、写入还是界面刷新上。该版当时只做源码排查，没有执行 Blender 性能测试，不能据此确定某个版本使生成时间增加了多少。

用户提供的失败日志中，口腔与牙齿接触计算 68.65 秒，左右眼部约束各约 25.6 秒，眼线与脸皮接触 21.77 秒，口腔与面部接触 17.17 秒；这几项的界面刷新合计约 6.94 秒。现有证据表明主要时间用于计算，单次 `Draw window and swap` 的 18.6 毫秒警告不是数组布尔错误的原因。日志没有堆栈，尚不能确定原始异常位置。

1.9.32 的失败报告增加 `error_type`、`traceback` 和 `failure_context`，控制台同时打印完整堆栈。对称眼眉符合顶点配对条件时只计算正侧，并取消镜像后的双侧重复修正；没有测量提速倍数。

## 导出一次生成的记录

1. 正常生成需要的表情，使用原有分区、校正曲线和选项即可。
2. 完成或出现可捕获的报错后，展开 ExpressionGen 的「详细信息」。
3. 点击「导出最近一次耗时报告」，保存 JSON。

报告始终记录，不需要勾选诊断选项。场景保留最近一次记录，成功生成的结果对象另存一份，属性名均为 `ek_generation_timing`。后续组合、预览或曲线写回会更新场景记录，因此需要比较的报告应及时导出。保存 `.blend` 时这些属性会一起保存；没有自动保存工程，也没有自动向外部目录写文件。强制结束 Blender 进程不会执行报告收尾。

## 怎么看报告

| 字段 | 用途 |
| --- | --- |
| `addon_version`、`blender_version` | 确认插件和 Blender 版本 |
| `metadata` | 操作类型、网格规模、输入/曲线签名、生成设置及跳过的表情 |
| `elapsed_seconds` | 生成上下文的总耗时；不包含保存报告的时间 |
| `work_seconds` | 扣除同步进度刷新后的耗时，包含计算、网格写入与其他阶段工作，不等同于 CPU 使用时间 |
| `redraw_seconds`、`redraws` | 进度更新、同步重绘及其面板/叠加层绘制耗时与次数 |
| `stages` | 各阶段累计耗时，从慢到快排列 |
| `batches` | 每个表情在计算、写入等批次的耗时；同名表情的不同批次分开记录 |
| `rows` | 按批次、表情和阶段交叉记录的明细 |
| `counters` | 本次执行的约束工作量，明细也保存在对应 `rows` 中 |

`depth_bbox_pairs` 是眼部/口腔深度约束扫描的包围盒配对数量；`depth_overlap_pairs` 是进入精确三角面投影重叠计算的候选数量。它们不是穿模数量。`lash_bbox_pairs`、`lash_overlap_pairs` 对应睫毛与脸皮检查。

`eye_path_weights` 记录实际眼部运动权重检查数，包括左右侧和重复修正轮次。`lash_eye_path_weights` 记录回收脸皮时复查眼部遮挡的权重数。`fold_iterations` 记录防翻折迭代数；`fold_triangle_evaluations` 包含迭代、步长尝试以及首尾验证中实际评估的三角面数量。

阶段名来自计算流程的进度标记，计时在阶段切换前累计，不受界面刷新节流影响。表情切换会单独结算，避免把上一表情的尾部工作归到下一表情。界面刷新时间与计算时间分开累计，不重复相加。

## 当前源码的重点疑点

以下版本归属来自更新记录，工作量来自当前源码。它们说明为什么可能变慢，不代表已实测确认回归。

| 版本或路径 | 当前行为 | 需要观察的证据 |
| --- | --- | --- |
| 1.9.10：`procedural_surfaces.depth_bounds` | 从少量采样扩大到完整投影重叠多边形。每批活动三角面与全部障碍三角面比较包围盒，再求精确交叠 | 眼部/口腔阶段耗时及包围盒、重叠候选数量 |
| 1.9.14：`procedural_constraints.finalize_skin` | 接触与防翻折最多交替三轮。双眼各 32 个运动位置，三轮最多有 192 次主要眼部路径扫描，另有终点修正 | `skin_constraint_passes`、`eye_path_weights` 及防翻折耗时 |
| 1.9.16：`generation_progress.Progress` | 同步刷新所有窗口；此前从绘制开始时计时，慢绘制会使下一步立刻再次刷新，每个表情还强制刷新 | `redraw_seconds`。1.9.26 已改为绘制完成后节流，生成时也跳过轮廓面板反复采样 |
| 1.9.20：`procedural_lashes.skin_behind_band` | 增加脸皮与睫毛实际交叠检查；修正脸皮后还要沿最多 32 个运动权重复核眼部遮挡 | 脸皮/睫毛接触、回收深度阶段及 `lash_*` 计数 |
| 1.9.22：`procedural_lashes.cover_closed_seam` | 按睫毛片截面检查遮缝并进行有界迭代 | 睫毛片覆盖和复核阶段耗时 |
| 1.9.24：自定义规则与变形曲线保存 | 每个表情准备规则及附属绑定，并保存可编辑的变形曲线 | 准备规则、保存变形后曲线阶段耗时 |

若主要耗时是包围盒配对，可优先改进空间索引和静态障碍缓存，保留精确检测。若耗时来自修正轮次，应先看哪些表情与约束重复触发。不能仅为加速减少路径检查数或关闭防翻折，否则会改变原有防穿模行为。

## 比较版本时保持输入一致

需使用相同模型、分区、校正曲线、勾选表情和幅度，并尽量保持 Blender 版本、视口和机器状态一致。先核对 `metadata`，再比较同一个表情的计算批次，排除表情数量和跳过项目的差异。签名一致有助于比较，但不同版本若改变签名算法，仍需核对原始输入。

当前工作区没有可直接复现该次变慢的完整 1.9.x 旧版归档，也没有同一输入的前后耗时记录。1.6.x 安装备份属于较早流程，不适合作为当前程序化生成的直接基线。即使暂时没有旧版，新报告也能先定位当前最慢的计算路径；确定回归版本仍需要对应旧源码或安装包，以及可比较的执行记录。
