# ExpressionGen：程序化表情制作

项目文件夹、安装包、Blender 插件列表和侧栏统一命名为 `ExpressionGen`。旧版导出的表情规则和已保存的分区预设仍可读取，场景属性沿用原有标识，保留模型中的设置与曲线引用。

## 下载与安装

支持 Blender 4.0 及以上版本。已在 Blender 4.5.14 LTS 验证安装和插件注册，其他版本尚未逐一运行验证。

1. 点击本仓库的「Code → Download ZIP」，或下载 [main 分支源码 ZIP](https://github.com/Loki-0228/ExpressionGen4Blender/archive/refs/heads/main.zip)。发布版本中的「Source code (zip)」也采用相同的插件目录结构。
2. 在 Blender「编辑 → 偏好设置 → 插件」的安装菜单中选择下载的 ZIP。无需解压、重新打包或选择仓库内的其他文件。
3. 搜索并启用「ExpressionGen」。已有旧版安装时，先停用旧版，避免同时启用两份插件。
4. 在 3D 视图按 `N`，打开「ExpressionGen」侧栏。

插件运行文件直接位于仓库根目录，GitHub 自动添加的外层目录用于插件安装。Windows 64 位原生加速库随源码 ZIP 提供，其他环境或加载失败时自动回退 NumPy 实现。开发模型、测试资料和本地打包工具不包含在下载包中。

## 当前版本

2.0.0 同版本更新补齐原始预设的闭眼睫毛随动。保留现有主睫毛带、闭眼轮廓、脸部和眉毛的求解结果，只让未手工编辑的游离睫毛跟随最终睫毛带。共享根部与手工控制保持；会新增播放过程翻折的整根睫毛保留原动作。

覆盖检查改为批量计算并复用边数据；Windows 64 位安装包包含覆盖约束循环的原生加速库，其他环境或加载失败时回退原 NumPy 循环。约束次序、采样、迭代上限与容差保持。进度增加「拟合睫毛覆盖约束」，避免耗时被错误归在上一条覆盖核对步骤。实测范围见 [检查记录](KNOWN_ISSUES.md)。

2.0.0 同版本更新修正已有预览再次生成时窗口长时间无响应的问题。界面按钮改为后台任务，准备输入后即可继续操作视图；原预览保留到新结果完成，按 Esc 可取消。生成期间修改模型、分区、曲线或设置会使本次结果失效，完成时会提示重新生成。插件卸载或打开其他文件时终止本次后台任务。

写回后再次生成会先验证目标基型。能确认只是上次写回改变了基型、且目标与分区拓扑仍一致时，继续使用已有分区及曲线；真实模型编辑或拓扑不一致会在求解前提示处理。后台生成使用相同表情求解器及约束。

安装包继续使用版本 2.0.0。本次修正带有既有形态键模型的写回：保留 Blender 原有形态键数据及动画结构，避免复制变换驱动时写入只读属性而失败。已有关键帧的 Action slot、NLA、驱动和相对键关系随网格副本保留。生成表情与旧键同名时更新形状，原控制器继续生效；其他旧键保持。安装更新并重新加载插件后，可对仍符合原分区、曲线和设置的生成结果重新执行写入，无需为此次写回修复重新计算表情。

此前的眼部分区修复也包含在该安装包中：先确认面部主体和眼部闭合结构，再按根部与主体的连接关系处理零散片。眼白的前环与后壳可通过重合边界组成同一候选；仅在一个点相碰、位于瞳孔前方或已有明确其他分区的面片不会据此合并。锁暝测试副本中原被误判为睫毛的 136 个眼白面已归回眼白。识别不依赖这三个测试模型的名称。

原有睫毛截面厚度、旋转、下翼锚点、闭合及接触约束保持。笑闭眼只增加原求解器未收敛时的可行性复核，仍使用原位移和曲率边界。月野兔、PING、Vody 的原分区与原曲线固定后，闭眼、笑眼、怒眼共 9 个生成结果与修改前逐顶点相同；球形眼模型的闭眼和笑眼也逐点一致。旧文件在未重新检测附件时继续使用原归属。新分区的效果和剩余问题见 [检查记录](KNOWN_ISSUES.md)。

更新后，若当前工作分区已有误标，需要修正该分区，或从未标记的模型副本重新创建分区，再更新校正曲线并重新生成表情。自动识别不会覆盖已有手工分区；已编辑曲线和手工指定的单根睫毛仍优先。旧形态键不会自动更新。最低安装版本仍为 Blender 4.0，本次实测为 4.5.14 LTS。

## 2.0.0 已有功能与修订

本轮同版本更新修正 PING 嘴角被收尖的问题。按唇缘实际走向识别回折，仅让存在回折的嘴角区域共用端点旋转；连续向内的唇缘保留原有圆弧开口。单排牙的牙缘贴合、闭嘴遮牙和吐舌支撑沿用此前约束。原始 Basis、分区、曲线和版本号均不变；安装后需重新生成形态键。

同版本更新重新校准上下牙动作：按 Vody 原始张口时各牙片的运动识别上下牙，修正旧参考中混入另一排牙片的问题。上牙小幅上移、下牙较大幅下移，已校准动作不再叠加随唇浮动。「い」等原参考静止的牙齿保持原位，仅补足目标模型原有咬合间隙。PING 唇缘中部尖点修正保留；安装更新后需重新生成形态键。

版本 2.0.0，最低安装版本为 Blender 4.0，不设版本上限。该范围依据当前代码使用的 API 确定，尚未完成跨版本运行验证。仅保留需添加表情的模型的程序化表情流程，源表情迁移、源材质抽取、源贴合和旧标准表情面板已退出主界面。

当前版本只保留原始预设，已移除「部件整体」实验方式及眼部约束选择框。生成、预览和组合表情统一使用原始方案。分区 3 合并瞳孔和高光，旧编号 5 继续兼容；现有曲线编辑和分区工作流程保留。旧实验结果需要重新生成后才能写回或组合。

本次同版本撤销愤怒眼统一向鼻侧内移。内眼角先平滑接入上睫毛主体，Face 眼缘随后贴合实际睫毛面片；原有外眼角小幅抬高保留。下睑延伸段仍跟随下眼睑，不将整圈脸皮当作睫毛截面旋转。三个模型的愤怒眼最终 Face 翻折检查为零，内眼缘覆盖及闭眼下睫毛遮盖检查通过。安装更新后需要重新生成形态键。

眼部接触沿用原始预设，按高光、瞳孔、眼白的顺序执行深度避让，保留原始层间间距和形状。「悲しむ」上睑动作减弱，最高点仍偏内侧，下睑主体移动不变。

生成面板新增「计算设备」，默认「自动 GPU」。Windows 上检测到 NVIDIA 驱动和 CUDA NVRTC 运行库时，三角面接触与遮挡计算使用 GPU；缺少依赖或调用失败时自动回退 CPU，并在完成提示、生成报告和耗时报告中显示原因。无需安装 CuPy，也不修改 Blender 的 Python 环境。其余曲线拟合、拓扑求解和形态键写入仍使用 CPU。本机 RTX 4070 Laptop 的 5 项表情对照为 CPU 43.2 秒、GPU 19.0 秒，写入坐标完全一致；这不是所有模型的固定加速比例。NVRTC 加载方式依据 [NVIDIA 文档](https://docs.nvidia.com/cuda/nvrtc/index.html)。

睁眼规则区分「じと目」「ジト目」「悲しむ」「怒り目」。悲伤眼的最高点靠近内眼角，用整条三次样条平滑下降曲线。愤怒眼内角与主体共用平滑弧线和旋转方向。闭眼睫毛沿用原始方案的曲线与接触约束，单眼派生表情继承对应规则。

闭眼时上睫毛沿 Face 接合线弯曲。单根睫毛、双眼皮及分离的上眼皮附属条带共用曲线变换，眉毛保持独立。整片睫毛执行向内贴脸和向外避让，保留截面厚度及 Basis 原有埋入区域。达到位移上限仍有接触时，报告保留待检查项。

大口型的唇缘深度位移沿曲线平滑分配，并限制鼻部采样造成的突然突出。唇缘周围的斜面随曲线转动，Face 与 Mouth 在镜像后重新接合。牙齿保留校准后的上下行程；参考中的前移若碰到目标嘴唇，先收回前移，再执行有界深度避让。「にやり」和「にやり２」加强整体笑弧，2 沿用 1 的嘴宽与笑线，保持闭嘴。闭嘴变形保留 Basis 的唇缘厚度和嘴角回折面，避免将它们压到同一条线上造成破面。两种歪嘴笑先将整条口型的竖向动作减到原来的 70%，再对上下唇施加统一倾斜，不单独移动某个嘴角。「にやり３」保留较小的张口，两者方向相同，均不参与强制左右对称。

「风格设置」提供下眼睑参与量、笑眼弧度和笑眼形态保持。它们调整可行范围内的曲线偏好，不关闭闭合、防穿模或厚度约束。生成列表仍只有勾选框与名称。已在 Blender 4.5.14 的物理副本中运行生成；完整性测试与视觉效果的范围、残余问题见 [检查记录](KNOWN_ISSUES.md)。

口型以 Vodyanitsa (Original) 的原始形态键为参考。ω、嘴角升降沿用原始唇缘，普通口型保留舌头随开口的整体位移与旋转。「てへぺろ」向一侧伸舌，「ぺろっ」居中向下卷。舌头截面沿参考曲线弯曲；目标舌头相对嘴巴过厚或过宽时，仅在吐舌形态中等比缩小，生成的 Basis 不变。实际接触可能限制参考动作，未消除的接触项仍写入报告。

「い」等参考上下牙不分离的口型优先保持咬合：已校准的上下牙不额外随唇浮动；目标原有小间隙由下牙整组上移至首次接触，不缩放牙齿、不改变 Basis。原参考已有张颌动作的口型按嘴宽适配上下牙各自的整体位移和旋转。缺少独立下牙分区时不生成不存在的下牙。

生成期间暂时禁用编辑，生成按钮原位显示同一行高的进度条，不插入额外进度框。顶部显示当前阶段，Blender 底部状态栏显示表情、阶段和耗时。轮廓检查信息及相关按钮沿用生成前的布局，不在进度刷新时重复采样曲线。完成或报错后恢复按钮并清除状态栏提示。

曲线可临时转换为一个雕刻网格，每条曲线对应独立材质和面组；可设置面片宽度、纵横细分和写回拟合段数。写回成功后删除编辑网格，保留曲线原有绑定。表情曲线副本沿用校正曲线的整体平滑拟合。入口位于「轮廓校正」和「自定义表情 · 曲线编辑」的「面片雕刻曲线」。

「强制左右对称」显示在生成按钮上方，无需展开表情选择。开启后，将正侧完成约束后的最终坐标镜像到负侧；对称面为 X=0 时即 `(x,y,z) → (-x,y,z)`。相关顶点可配对的独立眼眉只计算正侧，跨中线口型保留整体求解。子表情、组合和特殊表情除外。对细分不同的同分区网格尝试对侧表面绑定；找不到可靠对应时才跳过并说明原因。自定义规则可声明对称资格和表情依赖。生成列表只显示勾选框和名称，按预设完整幅度生成。

包含可迁移自定义表情、变形曲线副本写回、MD/JSON 规则导出和曲线左右对称，组合表情位于独立面板。表情滚动列表始终显示未勾选项目；重复校正曲线保留备份并自动归并。使用步骤见 [自定义表情说明](docs/custom_expressions.md)，全部内置表情规则见 [计算准则表](docs/expression_rules.md) 和 [可读取 JSON](docs/expression_rules.json)。

当前代码直接使用 Blender 4.0 的 `NodeTree.interface.new_socket`、`UILayout.progress` 和不带 `3D_` 前缀的 GPU 着色器名称，因此最低版本保留为 4.0。生成逻辑没有要求 4.5 的版本判断。依据见 [Blender 4.0 Python API 变更说明](https://developer.blender.org/docs/release_notes/4.0/python_api/)。驱动器复制只处理当前版本实际存在的可写属性。

生成完成或报错后，可在「详细信息」点击「导出最近一次耗时报告」。报告分别记录各表情、各计算阶段和界面刷新耗时，附带约束工作量与输入签名；1.9.32 起失败报告另存完整堆栈和失败阶段。无需开启诊断开关。定位方法见 [生成耗时排查](docs/performance_diagnosis.md)。

## 使用顺序

1. 选择需添加表情的模型。
2. 创建目标分区，默认按「形状与拓扑」识别，也可选择「仅按材质」。已有手工分区直接沿用；需要参考预设时，从「分区预设库」加载「已修正分区标准」，勾选「按已修正标准分区」。
3. 修正分区、同步半脸，标记口腔、牙齿与舌头。
4. 生成并编辑目标校正曲线。控制点和手柄直接决定后续生成规则，默认参与生成，不必另行保存或勾选。可开启曲线左右对称，或将当前侧镜像至另一侧。指定单根睫毛保留原有曲线显隐，完成后仍在网格编辑模式。
5. 生成表情，检查结果，再点击「写入目标并恢复显示」。确认时统一写回所选目标，并保留覆盖前备份。

生成器内置从 Vodyanitsa 提取的 62 个表情参数，不要求场景中存在 Vodyanitsa。暂不生成星星眼和脸红。原始参考参数保留在 `data/procedural_vody.json`，用户反馈修正在程序化规则中应用。

“单根睫毛”区域只保留“单独处理单根睫毛”开关。开启时，生成曲线按钮可检测单根睫毛；生成表情只读取当前已有的单根曲线标记，不临时检测并添加独立形变。关闭或没有标记时，睫毛随整体眼睑运动。

预览和生成会自动补齐尚未创建、且能从现有分区识别的必要曲线，不增添不存在的模型部件。用户主动删除的曲线保持删除；删去必要上下眼缘、整带或嘴唇曲线时，跳过依赖该部位的表情并提示原因，不生成只有半边的双眼闭合。手工编辑的现有曲线保留。预览是一份单独副本，修改后须再次点击更新，不是实时拖拽求解，也不会直接写回原模型。

分区直接读取工作副本上当前可见的材质标记，重排材质槽后也不以旧槽位覆盖当前标记。修改分区、曲线或生成设置后，重新生成结果即可应用修改；已有结果不会自动更新。顶部只显示“下一步：……”；生成数量、耗时和检查项放在折叠的“详细信息”中。

在「表情选择」中勾选当前预设要生成的表情，默认全部勾选。搜索和类别筛选只改变显示范围；全选、全不选、反选作用于当前显示项。Shift 点击连续勾选或取消，Ctrl 点击仅选该表情。列表没有幅度入口，旧版保存的幅度值不参与新一轮生成。所有勾选项使用预设完整动作，并经过接触、防翻折和口腔联动求解。

舌头使用常规分区编号 12，与其他分区共用标记按钮。“优先显示目前分区”按当前编号突出显示：对应面为 95% 不透明度并透过遮挡，其他面为 15% 不透明度且保留遮挡关系。此效果由视口覆盖绘制提供，关闭后恢复显示；不修改原模型材质或渲染透明度。需开启视口叠加层。

## 分区与预设

预设匹配按连通部件及材质边界划分候选，优先比较边界环、拓扑连接、尺寸比例、面积比例与部件排列关系。不使用最近点、最近面或空间距离门槛，不需要移动预设去贴合新模型。无法区分的部件保留待调整，手动标记优先。

「形状与拓扑」按连通部件、比例、左右配对和前后位置识别分区，材质名称作为辅助线索；不读取预设网格，也不读取形态键变化。识别结果仍需在第 3 步检查。已有手工标记保持优先，不存在的分区无需补齐。

新建未标记模型的分区时，还会识别与 Face 连成一体、共用材质的眼窝和口洞背面：以实际眼睛、牙齿或舌头定位闭环，再沿 Face 拓扑确认环后的内凹面。眼部背面归入眼白（7 / Blank stare），口部背面归入口腔（8 / Mouth），状态栏显示识别面数。仅给已有面重新分区，不创建替代眼白或口腔。已有标记模型不自动补处理；「仅按材质」不执行这项几何识别。

有真实口洞时，先用 Face 边界定位嘴部，再从前方脸皮提取唇缘。向内翻入的唇面可以是连接深处边界的局部带面，无需构成封闭口袋；口腔与脸部分离也可识别。候选必须属于面部主体，并直接接触真实口洞，或通过局部内翻面连接口洞。按前方脸皮确定入口，不再仅凭 Mouth 材质交界或内腔大小选取。找不到可靠入口时提示缺失，不回退到已排除的深处边界。

Face 没有独立眼口边界时，继续利用实际眼睛、牙齿或舌头定位入口，沿前视方向的朝向翻转边提取闭环，并验证后方内凹盘面。本版未改动 Ping 使用的内凹入口检测函数。唇缝很薄时仍允许内腔在后方扩展，不用唇缝高度限制内部体积。

口内分区正确且与 Face 连接时，曲线提取先使用实际共享接缝定位，避免口腔后壁、牙齿或舌头的范围把嘴部定位带偏。有侧支的边界补查真实闭环；仍优先使用接缝前方的外唇折返边。仅在接缝可见且连接外侧上下脸皮时使用接缝本身，不修改已有口内分区。

闭嘴且上下唇重叠时，沿各自连接的脸皮向外查找鼻侧、下巴侧的走向，绕开唇缝第一排翻入面的干扰；不跨越唇缘或绕过嘴角。检查曲线保存各分支的实际顶点链，闭嘴 Basis、生成及组合表情沿用这份归属。口腔口沿优先沿用共享唇缘的归属，分离口腔再结合壁面连接和检查曲线判断，取消按顶点平均高度重新分上下。不能确定的口腔环保留连续位移场，并在 `cavity_ambiguous_rims` 中报告。

「分区预设库（跨工程）」显示用户保存的命名预设。点击名称即可加载；超过 8 个时，从「完整列表」选择，再点击「加载所选预设」。选择项按文件名保存，刷新列表和插件重新注册后保留。修正分区后填写名称，点击「保存当前修正分区为预设」。同名保存自动增加编号，不覆盖已有文件。

已删除以月野兔为底模的内置默认分区标准，不再提供默认标准选项或缺失文件回退。用户自行保存的预设不受影响。命名预设位于当前 Blender 用户配置目录的 `ExpressionGen/region_presets`。其他位置的文件可点击「从 JSON 加载」，包括以前自行保存的 `face_region_standard.json`；加载后在「已修正分区标准」对象框中显示。此功能不会自动搜索或迁移其他 Blender 版本的配置。

## 本版约束

- 默认将结果 Basis 的上下唇闭合。缺少可靠口缘时跳过，并在状态中说明。生成结果并不自动覆盖原模型的 Basis。
- Basis 保留目标眼睛、高光、眼白的位置和间距。独立悬浮舌头按主体平面整体旋转放平，浮在唇缝上方时整体下移；不缩放舌头厚度或体积。闭眼由 Face 孔洞上下边界合拢、睫毛带覆盖接合处实现。瞳孔与高光作为一个部件平移，眼白单独求解。失败保护暂沿用闭眼眼宽 24%、睁眼 35% 的位移上限，报告记录需要的位移、实际位移和限幅情况。
- 眼窝背面与 Face 共用边缘顶点时，生成结果只在同一网格内部拆开共享顶点。眼白侧保留原始 Basis，脸皮侧参与闭眼；口洞背面按 Mouth 的连续口沿约束跟随嘴唇。保留 UV 与原材质映射，不分离新的眼白或口腔物体。
- 眼部和脸部直接写入主表情键，不生成「路径修正」辅助键或对应驱动。主表情键独立控制脸部；权重之间使用 Blender 的线性形态键插值。
- 眼缘、嘴唇恢复 1.9.3 的曲线参数对应，并检查参数始终处于 0～1 范围。修复 1.9.4 将数组索引混入曲线参数、导致脸部不对称的问题。仍按拓扑顺序建立对应，保留用户的曲线编辑。
- 水平下眼睑不下降，上移基础上限为眼高的 30%。笑闭眼弧顶附近可再多抬眼高的 10%，额度随弧顶位置偏移并向两端平滑过渡，弧顶处上限为 40%。竖向眼角段以转折为界参与旋转，可下降至转折高度。下眼睑上限作为内部约束固定，不提供独立调整选项。
- 眼缘优先拟合单段三次贝塞尔曲线。普通闭眼参考下凹曲率；「笑い」及其单眼子表情保持上拱；「なごみ」及其单眼子表情保持近乎平直。上下眼睑共用接缝，上眼睑可大幅下移。笑眼及平直闭眼通过整段高度、曲率和必要的倾斜调整适配边界，不逐点截断成另一种弧线；无法同时满足时跳过该表情并记录原因。
- 闭合弧线以当前眼角连线为基准，拟合上眼睑曲率，允许弧顶偏离中点。笑眼的角色曲率保持默认 0.85；向下凹的曲率先转为上拱，不能因形状保持变回 U 形。「なごみ」直接将实际上下睫毛片的截面中心排成直线，避免原网格与曲线的偏差重新带回弧度。风格和覆盖求解后进行连续内折与最终接触，几何不足仍会报告缺口。
- 上下 Face 边缘在完全闭眼时对应同一折线接缝，避免不同顶点数采样同一曲线仍留下窄缝。实际睫毛片按截面检查覆盖；左右从内向外采用同样的追踪顺序，脸皮深度修正共同求解，不把角色原有差异强制镜像。
- 下眼睑近乎竖直的眼角段以转折位置为界，随闭合程度绕 Y 轴转向并压缩 Z，转折处平滑衔接；水平段沿原曲线移动。此旋转只用于下眼睑的竖直段，上睫毛整带仍不逐段扭转。
- 「眼角上／下」控制外眼角；「下眼上」只抬下眼缘，中段最高 30%；「睫下」只使上眼缘与睫毛下垂，中段幅度为眼高的 12%。这些动作不混入闭眼时的眼角共同抬升。
- 眼缘与睫毛带共用通过实际节点的局部单调深度插值。眼球接触还受原上下眼缘推导的局部脸部轮廓限制，避免闭眼或睁眼时把 Face 顶出。眼线只向同侧相连的眼周贴合；无法同时满足的接触约束记入报告。
- 上睫毛竖向部分在闭合后向 +Y 连续弯曲，最高 85°，弯曲半径受原厚度限制；折弯过渡使用五次平滑权重，不压扁深度。上下睫毛分离的带状部件按整体确定归属，避免同一截面分别跟随上下眼缘。折入后仍可能与眼球冲突，报告记录待检查数量。
- 整体睫毛带先按原始脸皮附着点修正深度，每个截面整体平移，同一条带的修正用三次曲线拟合。保留原始埋入距离，接触修正受原始厚度和附着距离限制，避免为防穿插把整条睫毛推出脸部。仍有冲突的截面记入 `lash_band_depth_conflicts`。
- 原眼洞内可见的睫毛即使没有脸皮射线命中，也参与闭合后的遮挡约束；贴合所需的后退不能新增穿皮。睫毛贴合后检查实际重叠处的脸皮前突，在不越过眼睛和高光、不新增翻折的范围内平滑回收 Face 的 Y 位移。闭合上下眼缘共用平滑修正；残余冲突记入 `lash_skin_depth_conflicts`。
- 单根睫毛优先绑定同侧整体睫毛带；没有睫毛带时才绑定脸皮。根部前 20% 保持与附着点的相对形状，再向可弯曲的末端过渡；朝向仍采用统一微小外翻及用户编辑。单根按弧长变化补偿截面，尽量保持外露形状与体积；薄片按面积补偿。接触修正后的中心线保持沿根尖方向前进，未解决的冲突记入生成报告。
- 眉毛和双眼皮线的编辑偏移连续计算。眼部动作使脸皮遮住静止眉毛时，也会修正眉毛深度。每侧眉毛叠层共用一项深度修正，不添加固定间距。
- 双眼皮和未单独建曲线的上眼皮附属条带共用主睫毛带的平滑 XYZ 位移曲线，保留自身偏移与厚度；没有上睫毛带时跟随最终上眼缘。已识别为双眼皮候选的独立 Face 条不再仅凭高度二次改为眉毛。
- 眼皮运动按 Face 网格连接关系平滑传递，鼻梁附近不再按 X=0 硬切影响范围。固定远处脸皮、面罩外边界及另一侧眼缘；位移求解后不再重复乘衰减系数。嘴部继续使用局部旋转求解。
- 脸皮防翻折固定眼口轮廓，在已有位移及相邻区域修正 X/Z；唇周自由顶点还允许调整深度。修正沿 Face 邻接平滑，每步最多为局部平均边长的 8%，最终求解的修正额度为局部平均边长的 1.5 倍。只接受减少翻折且不新增原本正常三角面翻折的更新，最多交替处理三轮；不整体缩小闭眼或口型幅度。
- 眼部接触检查 Basis 到终点的 16 个权重。高光、瞳孔、眼白依次避让，后层保留前层需要的内收量。位移上限为闭眼眼宽的 24%、睁眼的 35%，Basis 不变；剩余接触和睫毛覆盖问题分别报告。
- Mouth 与 Teeth 使用三角面重叠检测，检查 16 个颌部运动权重。检测范围按当前 Face 口洞裁切，嘴唇遮住的区域不再触发口腔后推。口沿连接固定，内部修正受原有深度范围限制；无法满足的接触写入报告。
- 嘴型直接读取 `Vodyanitsa (Original)_mesh` 实际 Face 外唇边界的 20 组轮廓，按目标口宽和当前检查曲线适配。「い」保留扁口和紧闭的上下牙组；「お」采用原模型的圆润轮廓。上下牙参考另外按原始开口动作校准，不用牙片中心高度判断参考归属。
- `ω` 为唇中部上抬的 W 形；`口角上げ／下げ` 只改变嘴角，不驱动眉毛。
- 非吐舌动作按放平后的 Basis 约束牙齿与舌头前后间距。吐舌以实际舌头与唇口平面的交截轮廓定位，从上下唇中央伸出。仅出口附近可变薄，压缩上限为 15%，伸出口外后平滑恢复未压缩的厚度和弯曲形状；不足的出口空间通过嘴唇位移补足，口腔与牙齿随同一份口型求解。宽于口洞的舌头记录为待检查项，不自动缩窄。
- 口腔、牙齿保留在同一个网格内。牙齿的整体颌部平移和旋转由隐藏辅助骨架控制；口腔开合、内部颌部跟随及牙齿避让全部写入主形态键，避免连接处被骨骼再次旋转。共享口缘顶点在网格内部拆开，两份顶点保持同点播放。导出牙齿动作时需包含辅助骨架及驱动结果。
- 内置口型的上下牙先使用校准后的整体动作，不再追加竖向随唇弯曲。未校准的自定义或下颌动作仍以原始 Y 深度分配有界随唇变形，新增弯曲位移最多为口宽的 8%。两种路径均不缩放牙弓宽高，不改变 Basis；深度避让依据实际 Face 三角面。
- Face 控制外口。Mouth 前沿按拓扑顺序绑定到实际上下唇网格边，固定边的顶点及插值比例；独立口沿在结果 Basis 中主动贴近嘴唇，共用 Face 的点继续跟随对应脸皮。允许边界环在嘴角接触；内部沿相邻网格平滑传递开口位移，向后跟随颌部。连接处从 Basis 到终点与 Face 同步线性播放，牙齿避让不会移动固定连接点。
- 上下唇开口轮廓保持原有配方。开口时沿当前 Face 采样深度变化，以口宽的 10% 软限幅并拟合连续样条，避免某个采样跳到鼻部后拉坏唇缘。找不到连续表面时记录检查项。
- 唇缘附近的 Face 按拓扑距离分别跟随上下唇，沿整条唇线的局部坐标系变形；外圈平滑过渡。核心面带作为平滑目标，允许防翻折修正，不再将异常折面强行固定。Mouth 在强制镜像后重新贴合最终 Face 边缘。
- 校准后的「あ」上牙整体上移约口宽的 13.2%，下牙整体下移约 39.7%；旋转会使牙齿前部的实际行程略有不同。「あ２」分别约为 16.8% 和 71.8%，不是所有口型共用一个比例。未校准动作保留原有上牙 30% 随唇及下颌补偿。求解后的位移写入最终形态键或骨架。
- 牙齿与 Face 接触时，已校准动作可先收回参考前移，再按牙弓与嘴宽的较大值取 6.5% 深度额度整排后移，保留牙弓形状。未校准动作仍使用口宽 2.5% 的共同后移和 4% 的局部平滑变形，局部变形检查是否引入新的三角面翻折。Face 障碍按唇缘相连拓扑选取，包含斜面与内翻唇面，不因法线朝向改变而漏检。修正不足仍记录穿插，不通过前推 Face 补偿。
- 吐舌后检查实际出口外的下表面、外侧面与最终 Face 的三角面重叠，另一侧不提供接触约束。独立舌头整体平移进行接触修正，避免外露段被继续拉长；焊接舌头按原始 Y 截面处理。前伸总额度不超过舌长的 35% 与口宽的 22% 中较小者，剩余接触记入 `tongue_exterior_conflicts`。
- 两个吐舌动作在初次变形和最终接触后限制尺寸：边长不超过当前 Basis 的 1.04 倍，X/Y 跨度不超过 1.08/1.04 倍，Z 跨度不超过原厚度加舌长的 28%。平移不计为尺寸放大；限制量及最终跨度写入报告。焊接舌根与接触约束不相容时保留尺寸限制并报告待检查项。此约束不用于「舌広げ」。

## 人工检查

同版本更新也需要重新安装、重新启用插件并重新生成表情，已有生成结果不会被自动修改。

确认完成统一写回目标，不再提供「覆盖到需添加表情的模型」勾选框或仅确认结果副本的分支；结果副本用于写回前检查。写入对象始终是第 1 步「需添加表情的模型」选中的物体，面板显示「写入目标」名称。选择 `face` 就写入 `face`，即使该物体带有抽取来源记录，也不会继续追溯并改写其他模型。生成前核对分区归属，应用前核对目标引用、拓扑与 Basis；在独立数据副本中准备结果，保留目标材质、UV、顶点组及其他形态键，再替换目标数据并保留备份。完成后显示并选中目标。已写入目标的结果禁止重复覆盖。更换目标后必须重新生成。

分区计算读取当前面上实际分配的材质。替换或调整材质槽时，可识别的当前材质名称优先于旧槽位记录；普通材质名与插件标记材质均可使用。已有分区中的 Gaze 和 Eyes 在创建分区或检测曲线时合并为一个 Eyes 槽，保留网格和已编辑曲线。原模型材质不变。

生成时，第 5 步面板显示当前表情、处理数量、计算阶段、总耗时和阶段耗时。眼部遮挡、脸皮防翻折、睫毛和口腔接触计算会分步刷新；结束后状态显示总耗时。进度条按当前批次的处理数量计算，不预测剩余时间。计算仍在 Blender 主线程执行，单次矩阵或几何运算期间可能短暂停止刷新；当前版本没有中途取消按钮。

分区完成后，点击第 4 步「生成 / 补齐校正曲线」。按钮使用当前流程指定的目标分区，不要求退出选面模式或先保存分区。无法启用时，按钮下方显示缺少目标、分区关联不符或多个分区副本等具体原因。

本版移除旧工程的标记迁移、对象名猜测、曲线升级、设置回填和旧路径辅助键清理。不自动修复或迁移旧工程。当前版本的曲线编辑即时生效、场景保存与重开、跨工程分区预设和覆盖前备份继续保留。

新生成结果只包含 Basis 和主表情键，不添加路径修正键。Mouth 跟随和牙齿分层变形写入主表情键，颌部运动仍由内部骨架驱动。

本次运行范围为三个模型的 21 项眼部表情，以及月野兔与 PING 的 44 项口部表情；全部使用测试副本。打包编译与 ZIP 校验不代替这些功能和图像检查。限制见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。
